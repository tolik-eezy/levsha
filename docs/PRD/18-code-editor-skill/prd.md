# 18 — Code Editor Skill: Product Requirements

**Module:** Code Editor Skill
**Phase:** 2 (Separate Project)
**Status:** Draft

---

## 1. Overview

The code editor skill extends the text editor skill with development-oriented capabilities: project-level file navigation, language-aware editing, build/run integration, and Git operations. This is the skill that developers will use most — and it's the skill that powers the self-improvement system's source editing.

---

## 2. Functional Requirements

### 2.1 Project Navigation (CE-01)

| Field | Value |
|-------|-------|
| **ID** | CE-01 |
| **Priority** | P0 |
| **Requirement** | Users can navigate codebases with project-aware tools. |

**Tools:**

| Tool | Description |
|------|-------------|
| `code_open_project` | Set the working directory for a project. |
| `code_find_definition` | Find where a symbol is defined (grep-based). |
| `code_find_references` | Find all references to a symbol. |
| `code_project_tree` | Show project file structure. |
| `code_search` | Search code by pattern across the project. |

**Acceptance Criteria:**

- [ ] User can set a project root directory.
- [ ] Symbol search works across the project.
- [ ] File structure is displayed.

### 2.2 Build and Run (CE-02)

| Field | Value |
|-------|-------|
| **ID** | CE-02 |
| **Priority** | P0 |
| **Requirement** | Users can build and run projects via chat. |

**Tools:**

| Tool | Description |
|------|-------------|
| `code_build` | Run the project's build command (make, cargo build, etc.). |
| `code_run` | Run the project or a specific file. |
| `code_test` | Run tests. |

The LLM detects the project type from files present (Cargo.toml → Rust, Makefile → make, package.json → npm) and uses the appropriate build command.

**Acceptance Criteria:**

- [ ] Build tool detects project type and runs the correct command.
- [ ] Build output streams to the chat or split-view panel.
- [ ] Test results are formatted clearly.
- [ ] Build errors are highlighted.

### 2.3 Git Integration (CE-03)

| Field | Value |
|-------|-------|
| **ID** | CE-03 |
| **Priority** | P0 |

**Tools:**

| Tool | Description |
|------|-------------|

### 2.4 Language-Aware Editing (CE-04)

| Field | Value |
|-------|-------|
| **ID** | CE-04 |
| **Priority** | P1 |
| **Requirement** | The LLM provides language-aware code editing assistance. |

**Details:**

Because the LLM understands code, the code editor skill's prompt instructs it to:

- Respect language conventions (indentation, naming).
- Suggest appropriate patterns for the language in use.
- Explain code when asked.
- Refactor code based on natural language instructions.
- Generate tests for existing code.

This is not traditional IDE intelligence (LSP, autocomplete). It's LLM-powered editing where the user describes what they want and the LLM makes the changes.

**Acceptance Criteria:**

- [ ] LLM-assisted code editing respects language conventions.
- [ ] Code explanations work.
- [ ] Refactoring via natural language instructions works.
- [ ] Test generation works.

## 3. Relationship to Self-Improvement

The code editor skill and the self-improvement system share tools:

- Self-improvement uses `source_read`, `source_write`, `build`, `deploy` — these are specialized versions of the code editor's tools, scoped to the OS source tree.
- The code editor skill works on any project directory. The self-improvement skill works specifically on `/usr/src/levsha/`.
- Git tools are shared between both.

In implementation, the code editor skill's tools can be reused by the self-improvement skill with additional wrappers for checkpoint/rollback logic.
