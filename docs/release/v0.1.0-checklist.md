# Levsha OS v0.1.0 Release Checklist

Pre-release verification checklist for the MVP. Every item must pass before cutting a release ISO.

---

## Build Verification

- [ ] `make build` succeeds — release binary produced at `target/release/levsha-chat`
- [ ] `make stage` stages all artifacts into `staging/` without errors
- [ ] `make iso` produces ISO under 1.5 GB
- [ ] `bats tests/smoke_test.sh` — all 14 smoke tests pass
- [ ] `bats tests/final_validation.sh` — all validation tests pass
- [ ] `cargo test` passes all 79+ unit tests (run inside the Fedora build container)
- [ ] `cargo clippy --workspace` reports no warnings
- [ ] `cargo fmt --check --all` reports no diff

## Boot and Display

- [ ] ISO boots in QEMU (`make test-quick`) in under 30 seconds
- [ ] GRUB timeout = 0 (no boot menu visible; instant kernel load)
- [ ] Plymouth splash displays during boot (Levsha theme, no fallback spinner)
- [ ] Auto-login to `levsha` user (no login prompt)
- [ ] `cage` launches and `levsha-chat` occupies full screen (no desktop, no panel)
- [ ] `Ctrl+Alt+F2` does NOT switch to a VT (getty tty2-6 masked)
- [ ] No white flashes, mode-switch artifacts, or flickering during transition

## Chat Functionality

- [ ] Welcome message appears on first boot (fresh database)
- [ ] User can type in the input bar and send with `Enter`
- [ ] Streaming responses render token-by-token (not all at once)
- [ ] Markdown **bold**, *italic*, and `inline code` render correctly
- [ ] Code blocks (```) render with syntax highlighting
- [ ] Markdown tables render with aligned columns
- [ ] Ordered and unordered lists render correctly
- [ ] `Ctrl+C` cancels an in-progress streaming response; partial text preserved
- [ ] `Ctrl+F` opens the search overlay
- [ ] `Ctrl+L` clears visible chat area
- [ ] Long conversations scroll smoothly; auto-scroll follows new content

## Tool Calling (sysinfo)

- [ ] "what is my uptime?" triggers `uptime` tool, result renders
- [ ] "show disk usage" triggers `disk_usage` tool, result renders
- [ ] "how much memory is available?" triggers `memory` tool, result renders
- [ ] "show cpu info" triggers `cpu_info` tool, result renders
- [ ] "list running processes" triggers `processes` tool, result renders
- [ ] "show network interfaces" triggers `network` tool, result renders
- [ ] Tool status indicator shows spinner while running, checkmark on success

## Tool Calling (package-manager)

- [ ] "install cowsay" triggers `package_install` tool, package installs successfully
- [ ] "search for htop" triggers `package_search` tool, results render
- [ ] "list installed packages" triggers `package_list` tool, results render
- [ ] "update all packages" triggers `package_update` tool, update runs

## Destructive Command Guard

- [ ] "remove curl" triggers destructive guard (risk classifier flags `package_remove`)
- [ ] Confirmation dialog appears before execution
- [ ] User approves -> command executes, result renders
- [ ] User denies -> cancellation acknowledged, no side effects
- [ ] Other destructive commands (e.g., `rm` via tool) also trigger the guard

## Persistence (SQLite)

- [ ] Messages persist across reboots (reboot VM, re-open — conversation intact)
- [ ] Kill `levsha-chat` process -> watchdog restarts it -> history intact
- [ ] "clear history" triggers confirmation prompt
- [ ] After clearing, database is empty and welcome message re-appears
- [ ] Database file exists at `/var/lib/levsha/history.db`

## Error Handling

- [ ] Invalid API key -> styled error message (not a Rust panic or raw backtrace)
- [ ] Network disconnect -> retry with exponential backoff -> error with Retry button
- [ ] Status bar shows connected/disconnected indicator
- [ ] Malformed API response -> graceful error, chat remains usable
- [ ] Tool execution timeout -> error rendered, chat remains usable

## Performance

- [ ] Idle RAM usage < 1 GB (measure with `free -m` after boot, before interaction)
- [ ] ISO size < 1.5 GB
- [ ] First token latency: under 2 seconds from API response start to screen render
- [ ] Boot to chat-ready: under 30 seconds total

## Security

- [ ] No hardcoded API keys in the shipped binary or source tree
- [ ] `config.toml` uses a placeholder key (`sk-ant-REPLACE_WITH_ACTUAL_KEY`)
- [ ] `sudoers.d/levsha-dnf` restricts passwordless sudo to `/usr/bin/dnf` only
- [ ] SELinux is set to permissive (acceptable for MVP)
- [ ] No world-writable files in `/etc/levsha/`

## Branding

- [ ] Plymouth splash matches Levsha brand colors (see `branding/colors.md`)
- [ ] IBM Plex Sans is the default sans-serif font
- [ ] IBM Plex Mono is the default monospace font
- [ ] ASCII logo (`branding/ascii-logo.txt`) appears in welcome message
